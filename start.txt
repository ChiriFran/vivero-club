# PROMPT: Landing Page de Suscripciones tipo BAWAX CLUB

## Objetivo

Crear una nueva landing page independiente para suscripciones mensuales (ej: "BVOX" / cajas mensuales con plantas, macetas, productos seleccionados, etc.), replicando EXACTAMENTE el flujo de suscripciones del proyecto "buenosaireswax" (Club de Vinilos / Bawax Club).

Debes analizar y replicar el patrón funcional: formulario multi-step, guardado de datos en Firestore ANTES del checkout, creación de suscripción vía MercadoPago (Preapproval/Subscription checkout), redirección al checkout, y sincronización de estados vía Webhooks.

## 1. ANÁLISIS DEL PROYECTO BASE (Referencia obligatoria)

Usa como referencia el comportamiento actual del repositorio existente en `D:\proyectos\buenosaireswax` para comprender el flujo, pero crea un proyecto NUEVO y AUTÓNOMO (no modificar el original).

Flujo base identificado (obligatorio a replicar):

### 1.1 Frontend (Club de Vinilos)
- Página pública: `src/components/VinylClubPage.jsx`
- Estilos: `src/styles/VinylClub.css`
- Formulario multi-step (4 pasos): 
  1. Datos personales (nombre, instagram opcional, DNI)
  2. Contacto (email, teléfono)
  3. Envío (dirección, piso/depto opcional, ciudad, código postal)
  4. Preferencias (selección múltiple de géneros: House, Techno, Deep)
- Estados: `loading`, `error`, `exito`, `yaSuscrito` (si ya existe doc con `activo: true`)
- Al enviar formulario (submit final):
  1. Valida por paso (validación inline con touched)
  2. Genera `subscriberId = email.trim().toLowerCase()`
  3. Lee `doc(db, "clubvinilos", subscriberId)` en Firestore. Si existe y `activo === true` → muestra pantalla "ya sos parte"
  4. Crea/guarda documento completo en Firestore con estado inicial: `activo: false, pendiente: true, mercadopago_preapproval_id: null, mercadopago_status: null, fechaAlta: ISOString`
  5. Llama a `crearSuscripcion({ email, nombre })` (utils/mercadopago)
  6. Si recibe `checkout_url` o `init_point` → guarda email en `localStorage("vinylClubEmail")` y hace `window.location.href = checkoutUrl` (redirección inmediata a MP)
  7. Si falla MP → muestra error, NO redirige
- UI post-envío: pantalla de éxito solicitando revisar email (cuando redirigió a MP pero aún no está autorizado) y pantalla distinta si ya activo.

### 1.2 Backend (API Routes - Vercel style)
Carpeta `api/mercadopago/`:
- `crear-suscripcion.js`:
  - POST. Valida `email, nombre` (requeridos). Devuelve 400 si faltan.
  - `subscriberId = email.trim().toLowerCase()`
  - Busca/crea doc en colección `clubvinilos/{subscriberId}`. Usa `{ merge: true }` al setear: escribe `mercadopago_plan_id = MP_PREAPPROVAL_PLAN_ID`, `mercadopago_preapproval_id = null`, `mercadopago_status = "pending"`
  - Si doc existe y `data().activo === true` → 400 "Ya tenés una suscripción activa."
  - Responde 200 con: `{ init_point, checkout_url, preapproval_plan_id }`. `checkout_url = https://www.mercadopago.com.ar/subscriptions/checkout?preapproval_plan_id=${MP_PREAPPROVAL_PLAN_ID}`
  - Hardcode: `MP_PREAPPROVAL_PLAN_ID = "b9a00d38781c426a86372c2105819cf7"` (usar este patrón: ID de plan/preapproval_plan configurable por ENV)
- `webhook.js`:
  - Soporta GET (health), OPTIONS (CORS), POST. Headers CORS: `Access-Control-Allow-Origin: *`, métodos GET/POST/OPTIONS, headers incluyen `x-signature` (importante para MP)
  - Tipos procesados: `subscription_preapproval`, `preapproval`, `payment`
  - Busca suscriptor por prioridad: 1) `mercadopago_preapproval_id == preapprovalId` (query), 2) `external_reference` (doc id), 3) `payer_email` (lowercase)
  - Obtiene estado desde MP: `fetchPreapprovalStatus(preapprovalId)` con Bearer `MP_ACCESS_TOKEN` → `https://api.mercadopago.com/preapproval/${preapprovalId}`
  - Mapeo estados → flags: `authorized` → `{ activo: true, pendiente: false }`; `paused` → `{ activo: false, pendiente: true }`; `cancelled` → `{ activo: false, pendiente: true }`. Actualiza `mercadopago_status = status`
  - En `authorized`: setea `fechaPrimerPago = ISO` si no existe, `fechaUltimoPago = ISO`, `fechaProximoCobro = body.data?.next_payment_date || null`. Crea documento en `historialPagos` (subcolección) con: `{ fecha: ISO, estado: "authorized", monto: number, mercadopago_payment_id: payment_id|null, type: "payment" }`
  - En eventos `payment` (con `preapproval_id`): crea registro en `historialPagos` y actualiza `fechaUltimoPago`, `fechaProximoCobro`
  - Ignora casos desconocidos con 200 `{ status: "ignored", ... }`
- `status.js`: GET/POST para consultar estado por email (busca en `clubvinilos/{email}`)
- `cancelar.js`: cancela preapproval en MP (`DELETE/PUT` a `/preapproval/${preapproval_id}`) y actualiza doc a `activo:false, pendiente:true, mercadopago_status: "cancelled"`

### 1.3 Firebase Admin
`api/_lib/firebase-admin.js`: inicializa Firebase Admin con `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`. Normaliza `\n`/`\r\n` en private key. Singleton `getFirebaseAdmin()` + `getDb()` (Firestore).

### 1.4 Utils Frontend
`src/utils/mercadopago.js`: `crearSuscripcion(data)` hace `fetch(`${API_BASE}/mercadopago/crear-suscripcion`, { method: "POST", headers: {"Content-Type":"application/json"}, body: JSON.stringify(data) })` y retorna JSON.

### 1.5 Admin (referencia)
`AdminVinylClub.jsx` + estilos: lista suscriptores de `clubvinilos`, filtros, export CSV/XLSX. No obligatorio en landing pública pero útil para entender modelo.

9. INTEGRACIÓN MERCADOPAGO UTILS
src/utils/mercadopago.js:
const API_BASE = import.meta.env.VITE_API_BASE_URL || "";

export async function crearSuscripcion(data) {
  const response = await fetch(`${API_BASE}/api/mercadopago/crear-suscripcion`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(data),
  });

  const result = await response.json();
  if (!response.ok) {
    throw new Error(result?.message || "Error al crear la suscripción");
  }
  return result;
}
